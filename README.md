# Zyma Project: IIoT Cyber-Physical System for Kombucha Fermentation

Це — центральний репозиторій проєкту **Zyma**, кіберфізичної системи індустріального інтернету речей (IIoT), розробленої для моніторингу та керування процесом ферментації комбучі. Система реалізована в рамках бакалаврської кваліфікаційної роботи за спеціальністю 122 "Комп'ютерні науки" (ОПП "Інтернет речей") у Національному університеті "Львівська політехніка".

## Архітектурний огляд

Система побудована на дворівневій архітектурі за моделлю **Edge-to-Cloud**, що забезпечує високу відмовостійкість, швидкість реакції та розподілену обробку даних.

1.  **`zyma-cortex` (Рівень локального сервера):**
    *   **Залізо:** Raspberry Pi 3 Model B, що виступає в ролі центрального IIoT-хабу.
    *   **ОС та керування:** NixOS з декларативним керуванням через Flakes, що гарантує відтворюваність та стабільність середовища.
    *   **Роль:** Агрегація даних з Edge-вузлів, централізований MQTT-брокер (Eclipse Mosquitto), зберігання часових рядів та потенційно — платформа для розгортання SCADA-системи (наприклад, Node-RED) для візуалізації та керування верхнього рівня.

2.  **`zyma-spore` (Рівень Edge-вузлів):**
    *   **Залізо:** Мікроконтролерні вузли на базі ESP-WROOM-32.
    *   **Прошивка:** Високонадійна асинхронна прошивка, написана на чистому C++ (ООП) у середовищі PlatformIO. В основі лежить неблокуюча архітектура з асинхронними кінцевими автоматами для кожного сенсора та виконавчого пристрою, що забезпечує паралельне опитування та миттєву реакцію без затримок.

## Реєстр MQTT-топіків (ISA-95 Standard)

Система використовує динамічну структуру топіків, де в якості унікального ідентифікатора вузла (`[MAC_ADDRESS]`) автоматично підставляється очищена MAC-адреса мікроконтролера. Це дозволяє одночасно працювати з багатьма Edge-вузлами в одній мережі.

**Базовий префікс:** `kombucha/[MAC_ADDRESS]/`

### Системні топіки
*   `system/status`: Статус вузла ("online"/"offline"). Використовує механізм LWT (Last Will and Testament) для миттєвого оповіщення про відключення.
*   `system/debug`: Топік для виведення налагоджувальної інформації.

### Топіки керування
*   `control/target_set`: Запис цільової температури (°C) для ПІД-регулятора.
*   `control/run_set`: Запис стану процесу (1 - запущено, 0 - зупинено). Зберігається в енергонезалежній пам'яті.

### Топіки сенсорів
*   `sensors/bed_temp_c`: Температура нагрівального ліжка (NTC), °C.
*   `sensors/surface_temp_c`: Температура стінки ємності (DS18B20), °C.
*   `sensors/liquid_temp_c`: Температура рідини (DS18B20), °C.
*   `sensors/ambient_temp_c`: Температура навколишнього середовища (HTU21D), °C.
*   `sensors/ambient_humid_pct`: Вологість навколишнього середовища (HTU21D), %.
*   `sensors/digital_tvoc_ppm`: Концентрація летючих органічних сполук (AGS02MA), ppm.
*   `sensors/analog_ethanol_ppm`: Розрахункова концентрація етанолу (MiCS-5524), ppm.
*   `sensors/process_state`: Поточний стан автомата процесу (наприклад, "HEATING", "COOLING", "STABLE").
*   `sensors/heater_power_pct`: Поточна потужність нагрівача, %.

## Керування середовищами (PlatformIO)

Файл `platformio.ini` налаштований для гнучкого керування конфігураціями збірки та деплою, використовуючи механізм успадкування від базового середовища `[env]`.

### Середовища розробки:
*   `[env:esp32_cable]`: Базове середовище для прошивки та моніторингу через USB-кабель.
*   `[env:node1_main_ota]`: Середовище для бездротового оновлення (OTA) основного вузла.
*   `[env:node2_demo_ota]`: Середовище для OTA-оновлення тестового вузла (симуляція відмов).

### Основні команди (Fish Shell):

1.  **Надання прав на COM-порт:**
    ```fish
    sudo chmod 666 /dev/ttyUSB0
    ```

2.  **Збірка та прошивка через кабель:**
    ```fish
    pio run -e esp32_cable --target upload
    ```

3.  **Моніторинг через кабель:**
    ```fish
    pio device monitor -e esp32_cable
    ```

4.  **Бездротове оновлення (OTA) основного вузла:**
    *   *IP-адреса вузла має бути відома (статичний DHCP або mDNS).*
    ```fish
    pio run -e node1_main_ota --target upload
    ```

5.  **Бездротове оновлення (OTA) тестового вузла:**
    ```fish
    pio run -e node2_demo_ota --target upload
    ```
